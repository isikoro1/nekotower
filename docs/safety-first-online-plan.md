# Safety-first online plan

ねこタワーにオンライン対戦を追加するための安全方針です。
この文書の目的は、実装を急ぎすぎて公開中のゲーム、PC、課金、外部サービス設定を壊さないことです。

## 目標

- Webで2人オンライン対戦を遊べるようにする。
- GitHub Pagesの静的サイト構成を維持する。
- Firebase Realtime Databaseの無料枠で試す。
- 公開中のソロゲームを壊さない。
- 分からないところは小さく作って、スマホ2台で検証する。

## 絶対に避けること

- 既存のソロゲームを起動不能にする。
- Firebase設定値やルールを雑に公開して、誰でもDBを書き換えられる状態にする。
- 有料プランや課金が必要な構成に勝手に切り替える。
- 大量通信で無料枠を踏み抜く設計にする。
- `git reset --hard` や不要な削除で素材や実装を失う。
- オンライン機能が壊れた時にゲーム全体が壊れる構成にする。

## 安全な進め方

1. 設計書とAI向け指示書を作る。
2. Firebase設定ファイルは雛形だけをコミットする。
3. 実際のFirebase設定値は `.gitignore` 対象にする。
4. オンライン対戦ボタンは、設定がない場合は非表示または無効にする。
5. 最初はテスト用Firebaseプロジェクトで試す。
6. スマホ2台で最小対戦を確認する。
7. 人数制限、ルーム寿命、待機列上限を入れてから公開する。

## 実装の安全条件

- オンライン機能は feature flag 扱いにする。
- Firebase接続失敗時はタイトルへ戻すか、ソロゲームへ誘導する。
- Firebaseの初期化に失敗しても `src/game.js` のソロ処理を止めない。
- ルームデータは短命にする。
- 放置ルームはクライアント側の掃除処理で削除候補にする。
- DB更新はターン制に合わせて少なくする。
- 物理同期はホスト側を正にして、全端末で完全一致を狙わない。

## 無料枠を守るための初期制限案

- 最大同時対戦: 20部屋
- 最大待機人数: 100人
- 1ターン制限: 30秒
- マッチング待機の最大時間: 5分
- 放置ルーム削除: 3分以上更新なし
- スナップショット送信間隔: 対戦中のみ、必要最小限

## 切断時の方針

- UIではCPUとは表示しない。
- 表示は「通信が不安定です」「対戦を継続します」「相手のターン」など中立にする。
- 内部的には自動操作に切り替えて、対戦を継続できるようにする。
- 復帰できた場合の再同期は後回しでよい。まずは継続優先。
